Saint Demetrios Greek Orthodox Church in Seattle wanted to livestream the Divine Liturgy for parishioners who couldn't be there in person. I'm a software engineer and a member of the parish, so I started building it.

The first piece was the livestream itself. Each problem that came after it got its own tool: scheduling, streaming from the cloud, editing sermons, controlling cameras, lobby displays, and monitoring all of it. They share a calendar and a few APIs, and each one lives in its own repository.

The chapters below cover each piece.

# LiveStreamScheduler

Matches the parish calendar to YouTube broadcasts.

A command-line tool and web dashboard that reads upcoming services from the parish Google Calendar and checks which ones already have a YouTube broadcast. Matching is by start time. Services without a match show up as unscheduled, with titles and descriptions ready to copy into YouTube and Facebook.

  • Start-time matching between calendar events and broadcasts, with n-gram title similarity as a fallback
  • Mission Control dashboard with scheduled, recorded, and unscheduled views; reports stream to the page as they generate
  • Reference panel with saint and feast information for each service day, from the GOARCH feed and Synaxaria
  • Scope is scheduling and coverage analysis. Sermon editing lives in sermon-pipeline.

# YT Azure Streamer

A streaming VM that runs only when a stream is scheduled.

One ARM template deployment creates a VM that plays a recorded service from Blob Storage to YouTube Live with ffmpeg. Azure Automation starts the VM two minutes before each scheduled stream and deallocates it two minutes after, so compute is only billed while a stream is running.

  • Interactive deploy.sh and deploy.ps1 scripts check name availability, soft-deleted Key Vaults, and regional VM support before deploying
  • The stream key and web UI credentials live in Key Vault, and the VM reads them with a managed identity, so no secrets sit on disk
  • Recordings are mounted from Blob Storage with blobfuse2
  • Weekly schedules are edited in the web UI and synced to the Automation Account
  • Password-protected web UI behind Caddy: playlist editing, an up-next queue, start and stop controls, logs, and system monitoring. TLS comes from Let's Encrypt when a custom domain is set.

# Sermon Pipeline

Finds the sermon in a full-service recording and prepares it for YouTube.

A post-processing pipeline for broadcast recordings. It locates the sermon inside the full service, cuts it out, writes a title and description, and picks candidate clips for YouTube Shorts. The steps are exposed as tools on an MCP server that a VS Code agent drives, and skill files give the agent the Orthodox terminology and style rules the titles and descriptions need.

  • MCP tools for boundary detection, segment download, Shorts extraction, static-video rendering, and package validation
  • Sermon start and end come from the transcript. If that fails, the pipeline falls back to long silences, and a comparison script shows redetected boundaries next to the old ones.
  • Each sermon is its own directory with metadata, transcript, and boundaries. The index files are append-only JSONL and can be rebuilt from the directories.
  • Work is split by how mechanical it is: scripts for bulk jobs, tools for single actions, skills for judgment calls, and an agent to sequence them
  • Audio is normalized to -14 LUFS, and there is a batch workflow for the 2021 to 2024 archive
  • Fetches the weekly GOARCH Kids Sunday School lesson with headless Chromium and adds it to the liturgy description
Python MCP Playwright yt-dlp FFmpeg VS Code Agents

PTZ camera control from any browser.

A browser console for Panasonic AW-series PTZ cameras, with ONVIF support for other brands. A multi-camera dashboard puts each camera in its own controller with preset recall, live MJPEG/HLS preview, and a captures gallery. Sequences step through saved presets on a timer.

  • Multi-camera dashboard; each camera runs in its own iframe controller
  • Canvas-based virtual joystick for pan and tilt
  • Sequences run in auto, semi-auto, or boomerang mode, with a countdown to the next preset and a default speed per sequence

  • ONVIF through a PHP SOAP proxy that handles WS-Security digest authentication
  • Captures gallery with multi-select zip download
  • A written reference for the AW-HE40 CGI API, kept in the repo

# Church Calendar

A full-screen calendar for the lobby TVs.

A Flask app that shows upcoming events from Google Calendar as full-screen slides. Flyers and event images from local folders, Google Drive, or Google Photos are mixed in between the event slides. It runs on a Raspberry Pi Zero 2W and keeps showing cached events if the network drops.

  • Multiple Google calendars, cached locally with a 90-day look-ahead by default
  • Images are converted to WebP and resized so the Pi stays responsive
  • Six color themes, including a light one. Theme, font, slide speed, and margins are saved in the browser on each display.
  • The installer can be re-run safely, and sets up an AppArmor profile in complain mode
  • ntfy notifications when something goes wrong

# VideoKiosk2

Lobby TVs that show the livestream, then the calendar.

A Raspberry Pi kiosk that plays the HLS livestream in fullscreen VLC. When the stream freezes or goes away, VLC is stopped and a fullscreen browser opens a fallback page, which at the church is the calendar. A small scheduler polls an API for upcoming services and restarts the kiosk ahead of each one, so the stream comes back without anyone touching it.

  • Freeze detection by hashing screen captures, plus CPU-stall detection
  • Fallback browser is Midori on Raspberry Pi OS and Falkon on other installs
  • HDMI-CEC TV control. The TV goes to standby after the fallback page has been up for an hour, a delay that can be changed.
  • Optional Fire TV control over Bluetooth HID: standby, wake with Wake-on-LAN, and HDMI restore, with automatic reconnect
  • The standby countdown can be extended or shortened from the monitoring dashboard
  • Ubuntu AppArmor profile in complain mode, and ntfy alerts
  • The installer generates the wrapper scripts and settings, and can also be run through church-service-installer

# Church Monitoring

A dashboard for the church's AV hosts and devices.

A monitoring and control dashboard for the Raspberry Pis and other hosts that run the church AV. Each host runs a small client that collects metrics, and the server queries the clients on demand and caches the results. From the dashboard an operator can restart a service, switch a TV's input, set a standby timer, or take a screenshot of a kiosk's display. Server and clients authenticate each other with mutual TLS.

  • Pull-based: the server fetches from clients in parallel and caches the responses
  • Mutual TLS, with single-use tokens for enrolling new clients
  • Host actions: restart services, CEC power and input, and the standby countdown
  • Connectivity checks for devices that run no client, such as cameras and encoders
  • Remote screenshots of a kiosk's display through X11
  • Calendar image management from the dashboard: upload, archive, and restore
  • ntfy alerts on errors, and AppArmor profiles for the server and client CGI scripts

# MinerManager

Bitcoin miners that double as a space heater.

Seattle winters are cold, so some of the house's heat comes from bitcoin miners running Braiins OS instead of gas. MinerManager is the dashboard for them. It shows each miner's hashrate, power draw, efficiency, and fan speed, and it can change a miner's power target, enable or disable its pools, or pause and resume mining.

  • Per-miner hashrate, power, efficiency (W/TH), and fan speed with fleet totals, refreshed every 10 seconds
  • Power target from presets or a custom value, applied by editing bosminer.toml over SSH
  • Pool enable and disable through the CGMiner API
  • Pause and resume for individual miners
  • SSH key authentication, which replaced sshpass

# Ambient Streamer

A 24/7 streaming engine built around never restarting FFmpeg.

A headless engine for multi-channel, 24/7 streams. Each channel has a Liquidsoap audio process and an FFmpeg compositor that renders a color-adaptive image slideshow and an audio visualization, publishes to YouTube over RTMP, and serves a low-resolution HLS preview. YouTube can end a broadcast after a sustained gap in data, so the design rule is that FFmpeg never restarts, and every feature that changes the stream while it's live goes around that rule.

0.996×realtime speed
0dropped frames
~1.4 smake-before-break restart
  • Audio runs in its own Liquidsoap process behind an Icecast fallback mount. Restarting Liquidsoap measured a 0 s gap, where a direct connection stalled the compositor for 18 s.
  • Images arrive on a pipe, colors change over ZMQ, and visualization plugins switch with streamselect, all on the running filtergraph
  • When FFmpeg does have to restart (resolution, frame rate, encoder), the replacement starts before the old one stops. The gap measured about 1.4 s over 18 restarts, and YouTube sees a new ingest session.
  • A FastAPI control plane renders each channel's Compose file and runs the supervisor, watchdog, and scheduler. The operator UI is plain JS with live updates over SSE.
  • A channel can deliver to YouTube, to internal HLS video, or to audio-only HLS, and a LAN directory lists what is on air
  • Soundboard effects mix over the music behind an arm-then-submit control, without interrupting the stream

# Fitness Instructor Music

Class music that plays without a connection.

An offline-first web app for teaching a fitness class. One routine holds everything for a class: walk-in songs, the set list with timed cues, filler between songs, and walk-out songs. Saving writes to the device first and syncs to Azure when a connection is available, and a prepared class plays with no connection at all. A small group shares routines through owner, editor, and player accounts.

  • Local-first saves kept in IndexedDB and queued for cloud sync. A conflicting revision is never force-overwritten.
  • API on Azure Functions and Blob storage with ETag-conditional locks and immutable published revisions. Sessions use secure cookies, CSRF protection, and throttled sign-in.
  • Cue and exercise timing follows the audio clock, not UI timer ticks
  • Cues can be typed, imported from an Excel template, or dragged to a new time on the track scrubber. A cue can also flash the screen, and class mode keeps the screen awake.
  • Equal-power crossfades and silence or recorded filler between songs
  • Full-track loudness measurement (BS.1770 / EBU R128) and BPM estimates, both applied only after review
  • Service-worker offline shell and stored audio, an in-app update check, drag-to-reorder editing, undo and redo, and Excel and PDF cue-sheet export
TypeScript Vite Web Audio Service Worker Azure Functions Playwright
